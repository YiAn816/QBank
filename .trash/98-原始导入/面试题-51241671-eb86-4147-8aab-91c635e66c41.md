## 题目 1

问题一：多模型支持架构应该怎么设计？

### 知识点

- 分类：系统设计
- 模型网关统一调用 ChatString、ChatIniting 接口
- 底层 Adapter 适配不同模型（GPT、Claude、Gemini、DeepSeek）
- Router 根据租户、场景、成本、延迟选择模型

### 答案

设计一层模型网关，上层 Agent 不直接依赖模型厂商，统一调用 ChatString、ChatIniting 接口；底层用 Adapter 适配不同模型（如 GPT、Claude、Gemini、DeepSeek）；中间使用 Router 根据租户、场景、成本和延迟进行模型路由选择。

### 解析

核心是做一层模型网关。

## 题目 2

问题二：多租户场景下模型切换能否热更新？

### 知识点

- 分类：系统设计
- 必须配置化，不能写死在代码里
- 租户配置隔离
- 版本化切换（请求及配置快照）

### 答案

支持热更新，但不写死在代码里，需要配置化。每个租户拥有独立的模型配置（模型名称、参数、超时时间、版本号），切换时只改配置不重启服务，做到租户配置隔离、请求及配置快照、版本化切换。

### 解析

可以热更新，但必须配置化。

## 题目 3

问题三：Agent 的记忆工具调用知识库怎么实现？

### 知识点

- 分类：系统设计
- Memory 负责记忆保存短期上下文和长期用户信息
- Tool 负责工具调用，如查订单、发邮件、调用外部 API
- Trivia 负责知识库，从知识库召回资料交给模型

### 答案

将记忆工具调用拆成三个核心模块：Memory 保存短期上下文和长期用户信息；Tool 负责调用外部工具，如查询订单、发送邮件、调用外部 API；Trivia 负责知识库，从知识库召回资料再交给模型回答。

### 解析

拆成 Memory、Tool、Trivia 三个模块。

## 题目 4

问题四：一个 Agent 在系统里会有哪些状态？

### 知识点

- 分类：系统设计
- 状态机设计
- 常见状态包括已创建、执行中、知识库中、工具调用中等
- 复杂状态还有规划中、反思中、审视中

### 答案

Agent 要设计成状态机，常见状态有已创建、执行中等待模型、知识库中、工具调用中等待工具结果、暂停中、执行完成、执行失败、用户取消、执行超时，复杂一点还会有规划中、反思中、审视中等状态。

### 解析

Agent 要设计成状态机。

## 题目 5

问题五：后端 Agent 是否支持多租户并发调用？

### 知识点

- 分类：系统设计
- 数据隔离（会话、记忆、知识库不串）
- 配置隔离（不同模型、Prompt、工具）
- 资源隔离（流量、并发控制、配额）

### 答案

支持多租户并发调用，需要做好隔离：数据层面确保不同租户的会话、记忆、知识库不互相干扰；配置层面不同租户可以使用不同模型、Prompt、工具；资源层面进行流量限制、并发控制和配额管理。

### 解析

支持并发但要做好隔离。

## 题目 6

问题六：Session 和 UserID 如何绑定？

### 知识点

- 分类：系统设计
- UserID 表示用户，SessionID 表示会话
- 一个用户可有多个 Session，一个 Session 只属于一个用户
- 前端每次请求带 SessionID，后端校验属于当前 UserID 和 TenantID

### 答案

UserID 代表用户，SessionID 代表一次会话；一个用户可以拥有多个 Session，但一个 Session 只能属于一个用户。前端在每次请求中带上 SessionID，后端校验该 SessionID 是否属于当前 UserID 和 TenantID。

### 解析

通过 SessionID 与 UserID 校验绑定。

## 题目 7

问题七：Agent 的工具调用完整流程怎么走？

### 知识点

- 分类：系统设计
- 创建 Agent Run
- 加载上下文（历史消息、记忆、工具列表、知识库结果）
- 模型返回 ToolCall → 后端校验并执行 → 工具结果返回模型生成最终回答

### 答案

流程为：用户提问 → 后端创建一次 Agent Run → 加载上下文（包括历史消息、记忆、工具列表、知识库结果）→ 模型判断是否需要调用工具，若需要返回 ToolCall → 后端进行全局校验、参数校验并执行工具 → 工具结果返回后交给模型生成最终回答。

### 解析

完整流程包括创建 Run、加载上下文、模型返回 ToolCall、执行工具并返回结果。

## 题目 8

问题八：长期记忆和短期记忆有什么区别？

### 知识点

- 分类：系统设计
- 短期记忆为当前会话上下文
- 长期记忆为跨会话沉淀的信息
- 长期记忆需要持久化存储

### 答案

短期记忆是当前会话的上下文，包括用户本轮提问和模型本轮回复，服务于当前对话；长期记忆是跨会话沉淀的信息，如用户编号、项目背景、历史总结，通常需要持久化存储。

### 解析

区别在于上下文范围和是否持久化。

## 题目 9

问题九：SSE 在前后端之间如何交互？

### 知识点

- 分类：前端、计算机网络
- 前端与后端建立 HTTP 长连接
- 后端持续推送事件（Token 事件、ToolCall 事件、完成事件）
- 基于 SSE 协议的 Event + Data 格式

### 答案

SSE 本质是前端和后端建立一条 HTTP 长连接，前端发起请求后，后端持续向该连接推送事件，例如模型生成文本时推送 Token 事件，发生工具调用时推送 ToolCall 事件，任务完成时推送完成事件。

### 解析

基于 HTTP 长连接持续推送事件。

## 题目 10

问题十：后端推流通常采用什么数据格式？

### 知识点

- 分类：前端、计算机网络
- 外层 SSE 协议（Event + Data）
- 内层 Data 为 JSON
- 常见事件包括 StartToken、ToolCall、ToolResult、Status、Error 等

### 答案

后端推流一般采用两层格式：外层使用 SSE 协议（Event + Data），内层 Data 通常是 JSON，常见事件包括 StartToken、ToolCall、ToolResult、Status、Error 等。

### 解析

外层 SSE，内层 JSON。

## 题目 11

问题十一：Agent 工具调用时 SSE 事件通常包含哪些字段？

### 知识点

- 分类：前端、计算机网络
- 包含 RUNID、SessionID、AgentID、ToolCallID、ToolName、Arguments、Status、Result、ErrorCode、ErrorMessage、TimeStamp
- 工具开始时推送 ToolCall
- 工具成功或失败后推送 ToolResult

### 答案

SSE 事件通常包含 RUNID、SessionID、AgentID、ToolCallID、ToolName、Arguments、Status、Result、ErrorCode、ErrorMessage、TimeStamp。工具开始时推送 ToolCall，工具执行成功或失败后推送 ToolResult。

### 解析

包含运行时 ID、工具 ID、参数、状态、结果等字段。
