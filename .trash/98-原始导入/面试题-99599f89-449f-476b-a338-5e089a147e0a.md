## 题目 1

多 Agent 系统怎么拆角色？

### 知识点

- 分类：系统设计
- 按能力和责任边界拆
- 规划、执行和审核分离
- 共享状态由调度层统一管理

### 答案

按能力和责任边界进行拆分。将规划、执行和审核的职责分开，共享状态由调度层统一管理，避免单 Agent 各自为政。

### 解析

这题最容易达成角色分工，但面试官会追问冲突仲裁和状态污染。

## 题目 2

Agent 之间怎么传递信息？

### 知识点

- 分类：系统设计
- 传结构化状态不传完整对话
- 每条信息带来源和时间
- 敏感字段按权限过滤

### 答案

应传递结构化的状态信息，而不是传递完整的对话历史。每条消息必须携带来源和时间戳，对于敏感字段需按权限进行过滤后再传递。

## 题目 3

两个 Agent 结论冲突怎么办？

### 知识点

- 分类：系统设计
- 先比较证据来源
- 再按规则优先级裁决
- 不能让模型随口采信

### 答案

当两个 Agent 给出冲突结论时，首先比较证据的来源和可信度，然后根据预设的规则优先级进行裁决，在没有明确结果前，不能让另一个 Agent 随意采信。

### 解析

不能让另一个模型随口采取。

## 题目 4

怎么防止协作循环？

### 知识点

- 分类：系统设计
- 调度层设置最大轮次
- 交接必须协作原因
- 重复协作终止并转人工

### 答案

调度层需要设置协作的最大轮次上限，每次交接必须提供协作原因，若检测到重复的协作模式，系统应立即终止并转人工介入。

## 题目 5

### 知识点

- 分类：系统设计

- 分类：系统设计
- 统一 Task ID 串全链路

## 题目 8

如果一个 Agent 幻觉，污染了全局状态怎么办？

### 知识点

- 分类：系统设计
- 状态带置信度和来源
- 低置信内容不能成为事实
- 按状态版本回滚

### 答案

共享状态必须携带置信度和来源标识，低置信内容不能视为事实写入。发现污染后，应按状态版本立即回滚。

### 解析

共享状态要带置信度和来源，低置信内容不能成为事实。
