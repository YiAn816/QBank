## 题目 1

第一道题：知识图谱 Agent 适合解决什么问题？

### 知识点

- 分类：系统设计、算法
- 实体关系清晰
- 多跳查询
- 可解释推理
- RAG 结构化证据

### 答案

知识图谱 Agent 适用于实体关系清晰、需要多跳查询和可解释推理的场景，如企业组织商品关系、风险链路和专业知识。它不替代 RAG，而是为 RAG 提供结构化证据。

### 解析

通过明确实体关系、提供可解释的推理路径，为 RAG 补充结构化信息。

## 题目 2

第二道题：图谱构建从哪里开始？

### 知识点

- 分类：系统设计、算法
- 定义实体类型和关系类型
- 资源约束
- 文档/数据库/日志抽取
- 去重、消歧、人工校验

### 答案

先定义实体类型、关系类型和资源约束，再从文档、数据库和日志抽取实体关系，抽取后必须做去重、消歧和人工校验，不能直接把模型结果入库。

### 解析

系统化定义schema并对抽取结果进行质量控制，保证图谱可靠性。

## 题目 3

第三道题：实体消歧怎么做？

### 知识点

- 分类：系统设计、算法
- 名称/别名/上下文/来源/业务ID
- 确定性ID优先
- 文本相似度不足
- 模型辅助+可回滚

### 答案

通过名称、别名、上下文、来源和业务 ID 综合判断，优先使用确定性 ID；不只依赖文本相似度，模型可辅助判断，但合并结果必须可回滚。

### 解析

多维度信息融合确保实体唯一性，业务 ID 是最可靠的标识。

## 题目 4

第四道题：GraphRAG 和普通 RAG 怎么结合？

### 知识点

- 分类：系统设计、算法
- 普通 RAG 召回文本证据
- GraphRAG 召回实体关系路径
- 先定位实体再扩展关系
- 路径+文本一起给模型

### 答案

普通 RAG 召回文本证据，GraphRAG 召回实体关系和路径，复杂问题先定位实体再沿关系扩展证据，最后把路径和文本一起给模型，声称科技是回答。

### 解析

文本证据提供细节，结构化路径提供推理链路，两者互补提升答案质量。

## 题目 5

第五道题：图谱里的关系冲突怎么处理？

### 知识点

- 分类：系统设计、算法
- 关系带来源/时间/置信度/版本
- 保留多版本标记状态
- 冲突按最新/权威/高置信度来源排序

### 答案

关系要带来源、时间、置信度和版本，冲突不一定立即合并，可保留多版本并标记状态，回答时按最新、权威和高置信度来源排序。

### 解析

通过元数据管理冲突，支持多版本并存并在查询时动态选择最优关系。

## 题目 6

第六道题：知识图谱怎么做增量更新？

### 知识点

- 分类：系统设计、算法
- 增量更新仅影响实体关系
- 删除/修改需反向找相关边
- 记录影响范围
- 避免小变化全量重建

### 答案

新增文档只更新受影响的实体和关系，删除或修改要能反向找到相关边和所属，每次更新要记录影响范围，避免为了小变化全量重建。

### 解析

精准定位影响范围，提升更新效率，降低系统负担。

## 题目 7

第七道题：知识图谱 Agent 怎么防止幻觉？

### 知识点

- 分类：系统设计、算法
- 回答绑定实体/关系路径/文本证据
- 禁止模型自行补关系
- 多跳推理路径校验
- 每步回溯图谱或文档来源

### 答案

回答必须绑定实体、关系路径和文本证据，路径不存在时不能让模型自己补关系，对多跳推理结果要做路径校验，确保每一步都能回到图谱或文档来源。

### 解析

强制追溯证据，防止模型产生未经验证的幻觉信息。

## 题目 8

第八道题：如果图谱路径正确，但业务结论错了，怎么排查？

### 知识点

- 分类：系统设计、算法
- 实体消歧是否错误
- 关系是否过期
- 推理规则是否适用
- 路径正确不代表结论成立
- 图谱证据与业务规则分开验证

### 答案

先检查实体消歧是否错误，再检查关系是否过期，最后检查推理规则是否适用，路径正确不代表结论成立，因为业务规则可能有例外，难点是把图谱证据和业务规则分开验证。

### 解析

路径验证只是前提，业务规则的正确性仍需独立检查。
