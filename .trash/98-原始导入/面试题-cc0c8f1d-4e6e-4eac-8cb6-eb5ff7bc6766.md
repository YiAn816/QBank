## 题目 1

运维 Agent 可以接哪些工具？

### 知识点

- 分类：系统设计
- 工具分类：监控、日志、链路追踪、发布平台、告警平台
- 高危工具需单独审批：重启、扩容、回滚
- 读写工具必须区分

### 答案

运维 Agent 可以接监控、日志、链路追踪、发布平台和告警平台。高危工具如重启、扩容和回滚要单独审批。读工具和写工具必须区分，不能把生产权限直接交给模型。

### 解析

通过工具分类和权限控制确保 Agent 安全可控地操作生产环境。

## 题目 2

告警来了，Agent 第一步做什么？

### 知识点

- 分类：系统设计
- 确认告警范围和影响面
- 关联最近发布、配置变更和流量变化
- 先定位再处置

### 答案

告警来了，Agent 第一步先确认告警范围和影响面，再关联最近发布、配置变更和流量变化，不要马上给修复动作。运维场景里先定位再处置。

### 解析

强调运维场景的处置原则：先收集信息定位问题，再执行修复操作。

## 题目 3

日志太多，怎么让 Agent 查得准？

### 知识点

- 分类：系统设计
- 多维度缩小范围：服务名、时间窗口、Trace ID、错误码
- 工具层返回聚合结果和代表样本
- 保留原始日志引用

### 答案

先用服务名、时间窗口、Trace ID 和错误码缩小范围，工具层返回聚合结果和代表样本。异常日志要保留原始引用，不能把海量日志直接丢给模型总结。

### 解析

通过多维度过滤和采样机制，避免大量日志直接给模型造成处理压力。

## 题目 4

Agent 建议回滚，怎么判断能不能执行？

### 知识点

- 分类：系统设计
- 检查回滚版本、数据兼容和依赖服务状态
- 确认故障是否由发布引起
- 回滚要有审批和执行窗口

### 答案

先检查回滚版本、数据兼容和依赖服务状态，再看当前故障是否确实由发布引起。回滚要有审批和执行窗口，不能因为模型说可能有问题就直接回滚。

### 解析

回滚是高危操作，需要多重检查和人工审批，不能盲目信任模型建议。

## 题目 5

运维 Agent 怎么避免误操作？

### 知识点

- 分类：系统设计
- 高危动作二次确认
- 工具调用带幂等件和操作摘要
- 生产操作全链路校验和审批记录
- 默认只读模式

### 答案

高危动作要二次确认，工具调用要带幂等件和操作摘要，生产操作必须有全链路校验和审批记录，默认只读，确认后才进入写操作。

### 解析

通过多重安全机制（幂等件、操作摘要、审批记录、只读模式）防止 Agent 执行危险操作。

## 题目 6

怎么处理多个告警同时出现？

### 知识点

- 分类：系统设计
- 按服务依赖和时间线聚类
- 找到共同上游或共同变更
- 避免逐条独立处理
- 结合链路追踪定位

### 答案

先按服务依赖和时间线聚类，找到共同上游或共同变更，不要逐条独立处理，容易重复处置，更需定位要结合链路追踪。

### 解析

多个告警可能是同一根因引起，需要聚合分析而非独立处理。

## 题目 7

运维 Agent 的知识库怎么维护？

### 知识点

- 分类：系统设计
- Runbook 版本化并绑定服务和故障类型
- 历史事故提炼成结构化案例
- 及时下线过期命令和废弃服务

### 答案

Runbook 要版本化，并绑定服务和故障类型，历史事故要提炼成结构化案例，过期命令和废弃服务要及时下线，否则 Agent 会拿旧方案处理新系统。

### 解析

知识库需要持续维护更新，避免过时知识导致错误的处理建议。

## 题目 8

运维 Agent 怎么评估？

### 知识点

- 分类：系统设计
- 核心指标：定位准确率、平均恢复时间、误操作率、人工接管率
- 建议是否有证据链
- 评测集包含真实事故回放

### 答案

看定位准确率、平均恢复时间、误操作率和人工接管率，还要看建议是否有证据链，评测级要包含真实事故回放，不能只用简单问答评估。

### 解析

评估需要用真实事故场景，验证 Agent 在复杂场景下的实际表现。

## 题目 9

如果 Agent 自动扩容后服务恢复了，但成本突然飙升，怎么复盘？

### 知识点

- 分类：系统设计
- 查扩容触发条件、执行和持续时间
- 检查是否缺少缩容策略或成本上限
- 短期措施：设置容量上限并人工确认
- 长期措施：成本指标加入决策约束

### 答案

先查扩容触发条件、执行和持续时间，再看是否缺少缩容策略或成本上限。短期设置容量上限并人工确认继续扩容，长期把成本指标加入决策约束，不能只优化可用性。

### 解析

扩容需要平衡可用性和成本，需要设置成本约束并人工介入决策。
