## 1. 页面触发验证码或人机验证时，LLM Agent 应该如何处理？

#前端 #浏览器自动化 #安全

### 知识点
- 分类：前端、浏览器自动化、安全
- 识别验证状态并暂停自动化
- 不绕过或自动破解安全机制
- 用户接管后安全恢复
- 防止重复提交和状态过期

### 答案

验证码本质上是网站要求真人确认的安全边界，Agent 不应该尝试识别、破解或绕过。检测到验证码、滑动验证或二次认证后，我会暂停当前工作流，保存任务状态，并明确提示用户接管完成验证。

用户完成后，系统要重新读取页面和登录状态，确认会话没有过期、目标没有变化，再从安全检查点继续。提交类操作还要复核是否已经执行，避免暂停和恢复过程中发生重复提交。

### 解析

考点是安全边界与人机协作。OCR 可用于普通文档识别，但不应被用来规避验证码；完整回答还要说明暂停、接管、恢复和幂等处理。

## 2. 多页面操作时，如何保证 Agent 在多个标签页之间状态一致？

#前端 #浏览器自动化

### 知识点
- 分类：前端、浏览器自动化
- 为浏览器上下文和标签页建立稳定 ID
- 区分共享 Cookie 与标签页级 SessionStorage
- 并发控制和操作前状态校验
- 页面事件与任务状态统一记录

### 答案

我会给浏览器上下文和每个标签页分配稳定 ID，在调度层维护标签页的 URL、标题、加载状态、登录上下文和当前任务。要特别区分状态作用域：同一浏览器上下文中的 Cookie 往往共享，而 SessionStorage 通常是标签页级的，不能把两者当成一份状态复制。

多个页面并发操作时，要对共享业务资源加锁或做版本校验；每次动作前重新确认目标标签页和关键页面状态，页面跳转、关闭或登录变化则通过事件回传。不是只有活跃页才能操作，但后台页的执行能力和焦点依赖要由浏览器驱动明确管理。

### 解析

这道题考察浏览器状态作用域与并发一致性。仅维护“当前活跃页”无法解决多标签页任务，还要处理共享会话、标签页局部状态、焦点、页面生命周期和业务幂等。

## 3. 浏览器 Agent 为什么不能只靠截图识别和坐标点击？

#前端 #浏览器自动化 #自动化测试

### 知识点
- 分类：前端、浏览器自动化、自动化测试
- 截图提供视觉语义但缺少稳定身份
- 坐标受布局、缩放和遮挡影响
- 结合 DOM、可访问性树和视觉信息
- 高风险动作执行前复核目标

### 答案

截图能帮助理解页面外观和画布类内容，但坐标点击容易受到分辨率、缩放、滚动、弹窗和页面改版影响，也很难证明点击的元素就是目标元素。对于普通网页，我会优先使用 DOM 和可访问性树中的角色、名称、稳定属性与层级关系定位，再用视觉信息处理没有语义结构的区域。

执行前还要检查元素是否可见、可交互、没有被遮挡，并在点击后验证页面状态是否按预期变化。多种信号互相校验，比单独依赖视觉或选择器都更稳。

### 解析

考点不是否定视觉能力，而是根据页面类型组合结构化定位和视觉定位。DOM 可能过时或被复杂组件封装，视觉也会误判，因此需要多信号定位与动作后验证。

## 4. 页面存在弹窗、遮挡和滚动容器时，Agent 如何避免误操作？

#前端 #浏览器自动化 #安全

### 知识点
- 分类：前端、浏览器自动化、安全
- 识别模态框、遮挡层、滚动容器和焦点
- 按弹窗类型和风险分级
- 不自动确认未知或高风险操作
- 动作可追踪、可回放

### 答案

操作前我会先建立当前页面状态：是否有模态框或系统对话框、目标元素是否被遮挡、它属于哪个滚动容器，以及键盘焦点在哪里。对 Cookie 提示等低风险弹窗可以按策略处理；付款、授权、删除和未知弹窗则暂停并请求用户确认。

滚动时应滚动目标所属的容器，再重新定位元素，不能记住旧坐标直接点击。点击、输入、滚动和弹窗处理都要记录动作前后截图、元素标识和结果，这样失败后才能区分是理解错误、定位错误还是执行错误。

### 解析

完整答案需要同时覆盖页面状态识别、风险分级和可观测性。自动关闭所有弹窗或反复盲点会放大误操作风险。

## 5. 页面动态加载时怎么处理？

#前端 #自动化测试

### 知识点
- 分类：前端、自动化测试
- 等待业务条件而非固定 Sleep
- 超时、取消和有限重试
- 处理网络空闲、骨架屏和元素稳定性
- 失败原因可诊断

### 答案

我会等待与业务目标对应的条件，而不是写固定 Sleep。例如等待目标元素可见且可交互、某个网络请求完成、加载标志消失，或者列表数量达到预期。对于不断轮询或长连接的页面，不能简单依赖“网络完全空闲”，要选择更具体的完成信号。

等待必须有超时和取消机制，重试次数也要有上限。超时后记录 DOM、截图、网络错误和页面日志，区分是页面还在加载、元素条件写错，还是服务本身失败。

### 解析

动态等待的核心是等待状态而不是等待时间。可靠实现还要处理元素出现后继续移动、懒加载和虚拟列表等情况，并让失败可定位。

## 6. 页面改版后，怎么让 Agent 继续工作？

#前端 #浏览器自动化 #自动化测试

### 知识点
- 分类：前端、浏览器自动化、自动化测试
- 使用稳定业务属性和可访问性语义
- 多锚点定位与置信度
- 重新定位后验证元素意图
- 页面契约、监控和回归测试

### 答案

首先尽量和页面提供方建立稳定契约，例如 `data-testid`、ARIA role、可访问名称或业务 ID，避免依赖很长的 CSS/XPath。没有稳定属性时，再组合文本、角色、层级、邻近标签和视觉特征做多锚点定位，并给匹配结果设置置信度。

页面变化后可以尝试重新定位，但不能找到“看起来相似”的元素就直接操作，尤其是高风险按钮。要验证元素语义和操作后的业务状态；低置信度时暂停。线上还应监控定位失败率，并用代表性页面快照做回归测试。

### 解析

页面变化是正常演进，不应只靠一个写死选择器。自愈定位需要边界和验证，否则可能把“脚本不中断”换成更危险的误操作。

## 7. 元素定位采用什么优先级更稳定？

#前端 #浏览器自动化 #自动化测试

### 知识点
- 分类：前端、浏览器自动化、自动化测试
- 优先稳定业务属性和可访问性语义
- 组合角色、名称、标签和层级
- CSS/XPath 作为可控补充
- 坐标定位作为特定场景兜底

### 答案

我的优先级通常是：稳定业务属性或测试 ID，其次是可访问性角色和名称，再结合标签、文本、父子层级和邻近关系。CSS 选择器和 XPath 并不是不能用，但要避免依赖易变的自动生成类名、绝对层级和数组下标。

坐标点击只在 Canvas、远程桌面等缺少结构化语义的场景兜底，并结合截图重新确认。无论用哪种定位方式，动作前都要检查唯一性、可见性和可交互性，动作后再验证结果。

### 解析

稳定性来自语义和业务契约，而不是某一种选择器语法。`data-testid` 也可能被滥用，XPath 也可以写得稳定，关键是属性是否有明确且长期的含义。

## 8. 怎么判断一个网页任务真的完成了？

#前端 #浏览器自动化 #自动化测试

### 知识点
- 分类：前端、浏览器自动化、自动化测试
- 区分动作成功与业务成功
- 使用页面、网络和后端状态证据
- 处理二次确认、风控和未知状态
- 写操作具备幂等与补偿能力

### 答案

我会先为任务定义可验证的完成条件，而不是把“按钮点到了”当成成功。比如提交表单后，可以综合检查成功提示、页面数据变化、对应网络响应和后端记录；具体需要几层证据取决于任务风险，不必机械要求所有信号都存在。

如果出现验证码、二次确认、风控拦截或结果未知，Agent 应暂停或查询最终状态，不能继续重复点击。对于写操作还要使用幂等键，并区分已成功、明确失败和状态未知，必要时进入补偿或人工处理。

### 解析

考点是基于业务后置条件验收。动作执行、接口返回和业务落库是不同层次，可靠 Agent 必须知道什么时候继续、查询、回滚或求助。

## 9. 复杂网页的 DOM 过大，如何降低 Token 消耗和处理延迟？

#前端 #浏览器自动化 #大模型

### 知识点
- 分类：前端、浏览器自动化、大模型
- 基于任务裁剪可见和相关节点
- 使用可访问性树或语义化页面表示
- 保留元素 ID、层级和交互状态
- 防范网页内容中的提示词注入

### 答案

我不会把完整 HTML 直接送给模型，而是先在浏览器侧提取面向任务的页面表示：保留可见或相关的交互元素、可访问性角色、名称、状态、必要层级和稳定元素 ID，去掉脚本、样式、重复导航和不可见噪声。长列表可以只提供当前窗口，并通过工具按需查询更多节点。

这种压缩不能只追求短，还要保留元素之间的关系和后续可执行的引用。网页文本属于不可信数据，应与系统指令隔离并标注来源，避免页面中的恶意内容被模型当成操作指令。

### 解析

关键是任务相关的结构化裁剪，而不是简单把 DOM 转成 Markdown。既要降低 Token，也要保证元素可定位、状态可验证，并处理间接 Prompt Injection。

## 10. Agent 执行长链路网页操作时，如何处理中断和恢复？

#前端 #浏览器自动化 #分布式系统

### 知识点
- 分类：前端、浏览器自动化、分布式系统
- 显式状态机和持久化检查点
- 区分可重试动作与不可逆动作
- 恢复前重新读取页面和业务状态
- 幂等、有限重试和人工兜底

### 答案

我会把长流程建模成显式状态机，每一步记录输入、页面标识、业务对象、执行状态和可验证的后置条件。网络或页面故障后，不是直接回到上一步重做，而是先重新打开或读取页面，查询业务侧最终状态，判断这一步是未执行、已成功还是结果未知。

只读和天然幂等的动作可以有限重试；提交、支付、删除等不可逆动作必须使用幂等键或人工确认。检查点保存的是恢复所需的业务状态，不只是截图和 URL，因为页面本身可能已经变化。多次失败后应安全停止并提供清晰的人工接管信息。

### 解析

网页流程通常无法像数据库事务一样自动回滚。考点是状态机、状态查询、幂等和补偿，而不是假设刷新页面就能恢复到过去的安全状态。
