## 1. 代码 Agent 的权限边界应该怎么设计？

#Agent安全 #权限控制

### 知识点
- 会话级、工作区和工具级权限
- 路径规范化与软链接防护
- 最小权限和临时授权

### 答案

我会拆成三层。会话级权限决定本次任务能否读、写、执行命令或访问网络；工作区权限把文件访问限制在授权目录，并解析真实路径，防止 `..` 和软链接绕过；工具级权限则按风险开放具体能力。

默认只给完成任务所需的最小权限，授权带范围和有效期。删除、发布、访问凭证等高风险动作还要经过独立策略校验和用户确认，不能只靠 Prompt 约束模型。

### 解析

核心是纵深防御。真正的权限边界必须由文件系统、沙箱和工具网关强制执行。

## 2. 登录态怎么安全复用？

#身份认证 #浏览器自动化

### 知识点
- 凭证安全存储
- 账号上下文隔离
- 高风险操作重新认证

### 答案

登录态应由受控浏览器上下文或凭证服务管理，Cookie 和 Token 不进入 Prompt、普通日志或配置。不同账号使用独立上下文，Agent 只拿短期句柄，不直接持有长期凭证。

转账、改权限等操作前重新确认当前账号和用户身份；退出、过期或撤权后立即失效，并审计哪个任务使用了哪个身份。

### 解析

复用登录态不等于复制 Token。完整设计包括安全存储、账号隔离、再认证、撤销和审计。

## 3. 高风险工具为什么要做人机确认？

#Agent安全 #人机协作

### 知识点
- 模型可能误解意图或受注入影响
- 确认参数、目标和影响范围
- 防止确认疲劳

### 答案

模型可能理解错意图，也可能受到恶意内容诱导。删除、外发、转账和改权限会产生真实副作用，所以执行前要向用户展示目标、关键参数、影响范围和可撤销性，再获取明确确认。

确认不是唯一防线，系统仍要先做权限和参数校验；也不能每一步都弹窗，否则会产生确认疲劳。

### 解析

考点是确认的时机和内容。高质量确认必须具体、可理解，并由执行层验证。

## 4. 工具调用前的安全网关要做哪些校验？

#Agent安全 #工具调用

### 知识点
- 身份、租户和资源归属
- 工具风险、参数和业务状态
- 限流、幂等、审批与审计

### 答案

先校验调用主体、租户和目标资源归属，再确认工具是否在当前授权范围内。参数不仅要过 Schema，还要检查数值范围、业务规则、调用频率、幂等键和当前资源状态。

模型声称“用户已确认”不能作为授权证据，必须关联可信审批记录。网关还要记录策略版本和放行或拒绝原因。

### 解析

身份、资源、动作、参数和环境共同决定权限。只校验角色或 JSON 格式都不够。

## 5. 工具返回中包含用户隐私或敏感日志，怎么处理？

#数据安全 #隐私

### 知识点
- 源头最小化
- 进入模型前分级脱敏
- 原文加密、限权和限期保存

### 答案

先让工具只返回当前任务需要的字段，避免全量日志进入 Agent。返回后按敏感级别做脱敏或令牌化，只把最小必要摘要放进模型；密钥和完整身份信息默认不进入上下文。

确需保留原文时要加密、审批访问并设置保留期限。模型 Trace、评测集和应用日志也要遵守同样规则。

### 解析

最有效的措施是少取数据，而不是先收集全部再依赖脱敏补救。

## 6. 命令执行权限应该怎么控制？

#系统安全 #沙箱

### 知识点
- 沙箱和最小权限
- 完整命令与参数风险分析
- 资源限制和输出脱敏

### 答案

命令必须在独立沙箱中运行，只开放授权目录和必要工具，网络、子进程和系统调用默认受限。风险判断要分析完整参数、路径、重定向和管道，不能只看命令前缀。

执行时限制 CPU、内存、进程数、时间和输出大小。安装依赖、删除文件、访问公网或改系统配置需要审批，输出进入模型前先过滤凭证和环境变量。

### 解析

相同命令前缀可能因参数产生完全不同的风险，必须结合解析、沙箱和审批控制。

## 7. 模型输出了不该知道的信息，怎么排查？

#数据泄露 #故障排查

### 知识点
- 先止损并保留证据
- 排查上下文、记忆、检索、缓存、工具和训练数据
- 按当时权限和版本回放

### 答案

先限制相关功能或数据源，保存会话、Trace 和策略版本，再确认内容是否真实以及影响范围。随后沿数据链排查上下文、长期记忆、RAG、缓存、工具返回、日志和训练数据。

用当时的用户、租户、权限和组件版本回放，找到信息第一次进入链路的位置。若涉及真实个人数据，还要启动正式安全事件流程。

### 解析

不能把所有异常都归因于幻觉。系统应能回答信息来自哪里、为何被当前主体看到。

## 8. 日志要不要记录租户数据？

#日志 #多租户 #合规

### 知识点
- 最小必要与默认脱敏
- 使用租户和资源引用 ID
- 明文排障临时授权

### 答案

可以记录审计所需的租户标识、资源引用和安全事件，但不应默认保存完整业务正文。个人信息、凭证和敏感字段要脱敏，正文尽量使用引用 ID。

确需明文排障时使用临时授权和受控查询，并限制导出与保留期限。日志平台本身也必须做权限隔离和访问审计。

### 解析

没有租户上下文无法审计，保存过多正文又会制造新的泄露面，关键是分级和最小必要。

## 9. 恶意指令藏在会议纪要中并诱导 Agent 外部分享，怎么防？

#Prompt注入 #Agent安全

### 知识点
- 文档是数据而不是指令
- 工具调用绑定可信任务目标
- 外发动作独立授权

### 答案

会议纪要属于不可信数据，不能改变系统规则或直接触发工具。分享计划产生后，安全网关要核对动作是否来自用户明确目标、接收方是否授权、分享范围是否最小，并检查敏感信息。

外部分享应展示收件人和具体内容让用户确认。即使模型接受了纪要里的恶意指令，工具层也不能直接执行。

### 解析

这是间接 Prompt Injection。关键是指令与数据分离，以及执行前独立授权。

## 10. 确认太多影响效率，怎么平衡体验和安全？

#Agent安全 #用户体验

### 知识点
- 按风险分级
- 有范围和时效的授权
- 具体、可理解的确认

### 答案

我会按动作可逆性、数据敏感度和影响范围分级。低风险只读操作可以在明确范围内批量授权；中风险操作使用限定资源和有效期的会话授权；高风险写操作继续逐次确认。

确认框应明确显示将做什么、对谁和影响哪些资源。再结合拒绝率、撤销率、事故率和任务完成率优化策略，但不能因业务压力取消强制安全边界。

### 解析

目标不是确认越少越好，而是把摩擦放在真正危险的动作上。

## 11. 用户需要 Agent 修改文件时，怎么避免它乱改？

#代码安全 #权限控制

### 知识点
- 变更计划和文件级权限
- Patch、Diff 审核与测试
- 计划外变更重新授权

### 答案

先让 Agent 提交变更计划，列出文件、目的和影响范围，再把写权限限制到这些路径。执行过程保留 Patch；如果需要修改计划外文件，必须说明原因并重新授权。

完成后做 Diff 审核、测试、静态检查和敏感信息扫描。路径还要规范化，防止通过软链接或相对路径写出工作区。

### 解析

可靠控制包括事前限定范围、事中记录 Patch、事后验证，以及显式审批权限扩张。

## 12. Agent 错误点击并触发外部提交后，怎么收口风险？

#浏览器自动化 #事件响应

### 知识点
- 停止后续动作
- 查询最终业务状态
- 撤销、补偿与复盘

### 答案

先停止当前会话的后续动作并保留 Trace，再查询业务系统确认提交是否真正生效，不能因页面不明确就重复操作。若支持撤销或补偿，按当前业务状态执行；影响外部对象时及时通知。

之后回放定位、点击和确认链，判断是理解、定位还是执行错误，并为这类动作增加后置校验、幂等和必要的二次确认。

### 解析

处理顺序是止损、确认状态、补偿、评估影响和预防复发。网页返回通常不等于业务回滚。

## 13. 如何防止图片文字中的恶意工具指令？

#多模态安全 #Prompt注入

### 知识点
- OCR 内容按不可信数据处理
- 保留来源和区域
- 工具调用独立校验

### 答案

OCR 和视觉模型提取的文字都标记为来自图片的不可信数据，与系统指令分开。图片可以提供事实证据，但不能因为写着“调用某工具”就形成授权。

所有工具调用仍需绑定用户目标，经过主体、资源和参数校验；高风险动作要求确认，并保留图片 ID 和文字区域用于追溯。

### 解析

图片只是间接注入的载体。设计目标是即使模型受影响，执行层也无法越权。

## 14. 提示词里能不能直接放敏感权限信息？

#数据安全 #提示词工程

### 知识点
- Prompt 可能进入日志和评测
- 使用资源句柄和临时凭证
- 可信服务执行时解析

### 答案

不应放密钥、Token 和完整个人数据，因为 Prompt 可能进入日志、缓存和评测。模型通常只需要能力描述或资源句柄，不需要持有凭证本身。

执行时由可信网关根据句柄和当前身份获取短期、最小权限凭证。确需读取敏感字段时，要有明确授权、隔离和审计。

### 解析

关键是把理解任务和持有凭证分开；句柄本身也必须防止跨租户解析。

## 15. 推荐结果怎么做安全过滤？

#推荐系统 #内容安全

### 知识点
- 候选、排序和输出多层控制
- 年龄、地区、库存与合规
- 解释一致性和公平性

### 答案

候选阶段排除无权限、违法违规、不可售和不适用地区或年龄的内容；排序阶段加入质量、风险和多样性约束；输出前检查文案是否夸大、泄密或与商品事实不一致。

规则应依赖结构化商品属性和权威业务数据，不能只让模型看文案判断。高风险品类还需要人工治理、监控和申诉机制。

### 解析

安全过滤贯穿召回、排序和生成，不是最后一层关键词屏蔽。

## 16. 为什么只隐藏前端按钮不算权限隔离？

#权限控制 #前端安全

### 知识点
- 前端只控制展示
- API 和工具必须服务端鉴权
- 资源级授权和数据过滤

### 答案

前端隐藏只改变展示，攻击者或 Agent 仍可直接调用 API 或底层工具。真正的权限边界必须在服务端，对每次请求验证主体、动作和目标资源，并在查询层强制过滤数据。

前端可以改善体验，但即使可见性逻辑出错，后端也应拒绝越权操作。

### 解析

客户端不可信。角色权限和具体资源归属都要在服务端校验。

## 17. 线上发现租户看到了其他租户的检索结果，怎么处理？

#多租户 #数据泄露

### 知识点
- 止损、取证和影响评估
- 排查索引、过滤、缓存和重排
- 清理污染并回归

### 答案

这是高危数据泄露事件。先关闭问题路径或切到严格隔离方案，保存日志和索引快照，并按租户、时间和命中文档评估影响。

排查写入标签、查询过滤、缓存键、共享索引、重排后处理和权限同步。修复后清理受污染缓存与索引，用跨租户负向样本回归和灰度验证，再恢复流量。

### 解析

不能只补一行过滤条件。止损、取证、影响评估、全链排查和复测缺一不可。

## 18. 越权检测除了看用户角色，还要看什么？

#权限控制 #Agent安全

### 知识点
- 动作、资源、用途和上下文
- 任务意图与实际调用一致性
- 属性和关系级授权

### 答案

角色只说明大致权限，还要验证动作、资源归属、敏感级别、租户、用途和当前业务状态。例如有查询权限不代表可以批量导出或外部分享。

Agent 场景还要比较用户目标与实际工具调用，识别意图漂移。最终由后端基于主体、资源、动作和环境属性决策。

### 解析

意图一致性是附加风险信号，不能替代正式的资源级授权。

## 19. 怎么设计越权审计？

#审计 #权限控制

### 知识点
- 主体、租户、资源、动作和策略版本
- 记录决策、确认链和结果
- 防篡改、脱敏与保留期限

### 答案

每次敏感检索和工具调用都记录谁发起、代表哪个租户、访问什么资源、执行什么动作、关键参数、策略版本和授权结果。高风险操作还要关联用户确认或审批以及最终结果。

日志应具备防篡改能力，敏感字段脱敏并限制访问，同时用 Trace 串联模型决策与后端执行。

### 解析

审计要回答“谁在何时基于什么权限对什么资源做了什么”，只保存最终回复远远不够。

## 20. 知识库文档入库前要做哪些安全处理？

#知识库 #数据安全 #RAG

### 知识点
- 来源、授权和完整性
- 恶意文件、隐私和注入风险
- 权限、血缘、版本与删除同步

### 答案

先验证来源、所有权和授权范围，再做文件类型、恶意软件、敏感信息和内容质量检查。解析在沙箱中完成，文档指令作为不可信数据；但不能因文档讨论“越权”就直接隔离正常安全资料。

每个切片继承租户、权限、来源、版本和有效期。更新或删除文档时同步索引、缓存和派生摘要，并保留血缘。

### 解析

来源与权限是硬边界，关键词或模型给出的可信度只适合作为辅助风险信号。

## 21. Agent 安全和传统应用安全最大的区别是什么？

#Agent安全 #系统安全

### 知识点
- 动态、概率性的决策路径
- 不可信内容影响规划
- 工具组合扩大权限

### 答案

传统应用主要沿预设路径执行，Agent 会根据自然语言动态规划和组合工具，决策具有概率性；网页、邮件和文档还可能间接影响它的行为。

传统身份、权限和输入校验仍要保留，同时增加上下文隔离、计划与执行分离、工具风险控制、人工确认和全链路审计。

### 解析

Agent 安全是在传统安全之上增加决策和工具组合风险，不是替代传统安全。

## 22. Agent 安全评测至少要覆盖哪些场景？

#Agent安全 #安全测试

### 知识点
- 直接和间接 Prompt Injection
- 越权、泄密和危险工具
- 多轮、混淆和组合攻击

### 答案

至少覆盖直接和间接注入、跨租户和资源级越权、敏感信息套取、危险工具误触发、参数篡改、多轮绕过、编码混淆和组合攻击。

不能只看最终回复，还要检查模型是否尝试调用工具、哪一层拦截、是否产生副作用以及审计是否完整，并把线上新攻击持续加入回归集。

### 解析

评测对象是完整系统。模型拒答率不能代表权限和执行防线是否可靠。

## 23. Agent 越权访问怎么发现？

#异常检测 #审计

### 知识点
- 实时授权、审计与异常检测
- 跨租户、批量导出和频率异常
- 主动负向测试

### 答案

记录主体、资源、动作和授权决策，对跨租户访问、短时批量读取、异常工具组合和连续拒绝设置告警。同时使用蜜罐资源、跨租户负向测试和定期权限回归主动发现问题。

告警要能关联完整 Trace 和响应流程。审计不是唯一手段，服务端实时授权才是第一道防线。

### 解析

完整方案包括预防性授权、检测性监控、主动测试和事件响应。

## 24. Prompt Injection 要求 Agent 绕过权限，怎么防？

#Prompt注入 #权限控制

### 知识点
- 权限判断不交给模型
- 指令与不可信数据隔离
- 工具网关独立校验

### 答案

用户输入和外部内容不能改变真实授权状态。模型可以理解任务并提出调用，但工具网关必须根据身份、资源和策略重新校验，不能相信“管理员已经同意”之类的自然语言。

工具只开放最小能力，高风险动作要求确认。注入检测用于告警和降级，但不能作为唯一防线。

### 解析

目标不是保证模型永不受影响，而是即使受影响也无法越权执行。

## 25. 评测集应该固定，还是持续更新？

#评测 #工程实践

### 知识点
- 固定回归集
- 滚动挑战集
- 防止泄漏和过拟合

### 答案

两者都需要。固定集用于比较版本和发现退化，题目与口径保持稳定；滚动集吸收新的用户分布、故障和攻击，用于测试时效性。

新增样本要脱敏、去重并与训练数据隔离。固定集发现标注错误或业务失效时也应版本化更新，而不是永久不变。

### 解析

固定集保证可比，滚动集保证时效，同时要防止团队针对测试集反复调参。

## 26. 用户评价数据怎么用才安全？

#数据安全 #推荐系统

### 知识点
- 来源授权、隐私和反作弊
- 代表性与选择偏差
- 事实和主观观点区分

### 答案

先确认来源和使用授权，清理个人信息、联系方式和恶意内容，再做刷评与重复检测。生成摘要时保留不同观点和大致比例，不能只挑好评包装成一致结论。

主观评价不能改写成事实，涉及严重投诉时要保留来源与不确定性。用于训练前还要检查许可、去重和数据泄漏。

### 解析

安全既包括隐私合规，也包括不误导和避免选择性呈现。

## 27. 如何防止 Agent 泄漏敏感信息？

#数据安全 #Agent安全

### 知识点
- 数据分级和最小化
- 检索、缓存和工具的权限过滤
- 输出检查和外发控制

### 答案

在数据进入上下文前按敏感级别和租户做权限控制，检索、记忆、缓存和工具只返回当前任务必要字段，高敏数据脱敏或使用句柄。

输出阶段再做敏感检测和外发策略，下载、分享等动作单独授权。不能先把全量资料交给模型，再依赖它自我约束。

### 解析

输出过滤是最后防线，无法弥补上游已经让模型看到不该看的数据。

## 28. 什么是 Prompt Injection？

#Prompt注入 #大模型安全

### 知识点
- 恶意或冲突指令操纵模型
- 直接注入与间接注入
- 与传统代码注入的区别

### 答案

Prompt Injection 是攻击者通过输入内容影响模型遵循指令，诱导它偏离目标、泄漏信息或调用危险工具。它可以直接来自用户，也可以藏在网页、邮件、图片或文档中，后者属于间接注入。

它不是传统意义上的代码执行漏洞，防御重点是隔离不可信内容、最小权限和执行层校验，而不是寻找一个万能 Prompt。

### 解析

系统提示词泄漏只是结果之一，真正风险取决于模型可访问的数据和工具。

## 29. 外部网页和文档内容怎么防注入？

#Prompt注入 #输入安全

### 知识点
- 来源标记和指令数据分离
- 内容裁剪与最小暴露
- 工具调用重新授权

### 答案

网页和文档要带来源，以数据字段传给模型，不能拼进系统指令。只提取任务需要的内容，对隐藏文本、异常编码和高风险来源做检测，并保留引用。

过滤无法识别所有攻击，所以工具调用仍要根据用户目标重新授权；外发、写入和敏感数据操作需要确认或人工审核。

### 解析

模型未必始终遵守“外部文本只是数据”，必须依靠执行边界形成纵深防御。

## 30. 用户让 Agent 执行危险操作怎么办？

#Agent安全 #风险控制

### 知识点
- 判断合法性、授权和影响范围
- 可执行、需确认和禁止三类
- 安全替代方案

### 答案

先判断是否合法、用户是否有权，以及目标和影响是否明确。合法但高风险的任务可以缩小范围、先做只读预检或模拟执行，再让用户确认；越权、违法或无法安全控制的请求应拒绝。

拒绝时说明受限部分并尽量提供安全替代方案。用户的自然语言同意不能替代真实授权。

### 解析

危险不等于一律拒绝，也不等于用户要求就执行，关键是分级和最小影响范围。

## 31. 怎么处理模型输出不稳定带来的安全风险？

#Agent安全 #系统架构

### 知识点
- 模型只提出意图或计划
- 确定性后端执行策略
- Schema、状态机、幂等和审批

### 答案

模型输出限制为结构化意图、参数候选或计划，执行前由确定性代码做 Schema、权限、业务规则和状态校验。写操作使用状态机与幂等，高风险动作需要审批。

回归集、温度控制和版本治理可以降低波动，但设计目标应是即使某次输出异常，安全边界仍然稳定。

### 解析

稳定性优化只能降低概率，不能替代安全控制。

## 32. Agent 安全的核心原则是什么？

#Agent安全

### 知识点
- 默认不信任和最小权限
- 计划与执行分离
- 可确认、可审计、可恢复

### 答案

我会概括为四点：默认不信任自然语言和外部内容；只授予当前任务所需的最小权限；模型计划和真实执行分离；关键动作可确认、全链路可审计，并能安全停止和恢复。

能力越强，边界越要具体。上线前不仅要定义能做什么，还要明确不能做什么和失败时如何降级。

### 解析

核心是纵深防御、最小权限和可问责性，不能只依赖模型拒绝危险请求。

## 33. Agent 安全和普通大模型安全有什么不同？

#Agent安全 #大模型安全

### 知识点
- 内容风险与行动风险
- 数据访问、工具和真实副作用
- 模型输出与执行隔离

### 答案

普通大模型应用主要担心错误、有害或泄密内容；Agent 还会读业务数据、调用工具和改变外部状态，风险从“说错”扩大到“做错”。

所以除了内容安全，还必须有身份权限、参数校验、幂等、审批、沙箱和审计，并把模型输出与真实执行隔离。

### 解析

Agent 安全包含大模型安全，并增加行动和系统集成的攻击面。

## 34. 为什么 Prompt Injection 在 Agent 场景更危险？

#Prompt注入 #Agent安全

### 知识点
- Agent 能访问私有数据和工具
- 攻击可能产生真实副作用
- 工具组合扩大影响

### 答案

Agent 不只是生成文字，它还可能访问内部数据、发送消息或修改系统。被注入后，攻击者可能借用这些权限读取信息、组合多个工具并产生真实副作用。

风险取决于 Agent 的权限和工具，所以要减少可见数据和可用能力，让关键动作独立授权、可审计和可停止。

### 解析

该题强调危害放大机制，回答应落到权限、工具组合和副作用。

## 35. RAG 中的恶意文档怎么防？

#RAG安全 #Prompt注入

### 知识点
- 文档是证据而非指令
- 来源、权限和引用
- 生成与执行分层防护

### 答案

文档入库时记录来源、权限和版本，并做恶意文件与敏感信息扫描；检索片段作为带引用的不可信证据，不能成为新的系统指令。

关键结论要求引用，来源异常或证据冲突时降低置信度。任何工具动作仍经过安全网关，防止恶意文档从回答链路升级到执行链路。

### 解析

内容扫描只能发现部分攻击，必须结合来源治理、指令隔离和执行授权。

## 36. RAG 数据投毒怎么防？

#RAG安全 #数据投毒

### 知识点
- 写入权限、来源和完整性
- 版本、血缘、异常检测和审核
- 召回监控、引用与回滚

### 答案

先控制谁能写入知识库，验证来源和完整性，并记录文档、切片和索引的版本与血缘。对异常批量更新、重复内容、排名突增和权威来源冲突做检测，高风险更新进入隔离或人工审核。

答案保留引用并监控文档命中和错误反馈；发现投毒后能定位受影响版本、回滚索引，并清理缓存和派生数据。

### 解析

数据投毒会长期影响大量查询，防线要覆盖写入、索引、召回、监控和恢复全生命周期。
