## 1. 融合多个 LoRA 适配器时，如何减少能力遗忘和权重冲突？

#大模型微调

### 知识点
- 分类：大模型微调
- TIES Merging或DARE方法
- 参数差值裁剪缩放
- 冗余参数剔除
- 零样本推理指标监测

### 答案

我不会直接把多个 LoRA 权重相加。首先要确认它们使用同一个基座模型、作用在兼容的模块上，并分别建立目标任务和基座通用能力的验证集。然后从简单的加权合并开始调系数；如果不同适配器的参数更新方向冲突明显，可以尝试 TIES、DARE 一类的合并方法，或者不做静态融合，改为按请求路由、动态组合适配器。

合并后要分别回归每个业务任务、安全能力和通用能力。所谓“避免灾难性遗忘”不能靠某个合并算法保证，只能通过减少冲突、控制权重并用完整评测证明退化在可接受范围内。

### 解析

TIES、DARE 等方法只能降低部分参数冲突，不能保证能力不退化。回答应先讲兼容性、合并策略和替代架构，再强调多任务与通用能力回归；冲突明显的适配器更适合路由，而不是强行融合。

## 2. 多个业务共用基座模型，LoRA版本怎么管理？

#模型部署 #版本控制

### 知识点
- 分类：模型部署、版本控制
- 每个 LoRA 绑定业务数据集版本和基座模型版本
- 发布通过配置选择适配器
- 回滚只切换适配器不改基座模型

### 答案

我会把每个 LoRA 当成独立制品管理，记录基座模型及其校验值、训练数据集版本、代码和超参数、目标模块、评测结果以及安全审批状态。部署配置明确“业务—基座—适配器”的兼容关系，不能让不匹配的 LoRA 被误加载。

发布时使用不可变版本号，通过模型网关按租户或场景路由，并支持灰度、流量观测和一键回滚。回滚通常可以只切换适配器，但如果问题来自基座兼容性或共享推理服务，也要能够整体回退。

### 解析

版本管理不能只关注适配器文件，还要覆盖基座、数据、训练配置、评测和部署映射。多业务共享基座时尤其要防止错配、串用和某个适配器拖累共享服务。

## 3. 高并发在线推理场景下，多 LoRA 模型如何优化 Batching 性能？

#大模型推理 #GPU优化

### 知识点
- 分类：大模型推理、GPU优化
- Continuous Batching框架
- Punica框架
- MultiLora请求混批
- 算子融合减少显存拷贝

### 答案

我会先共享基座模型权重，只按需加载 LoRA 参数，避免每个业务复制一份完整模型。调度层采用 continuous batching，并根据适配器、序列长度和优先级组织请求；底层使用支持多 LoRA 的融合算子，让同一 Batch 中不同适配器的增量计算高效执行，减少权重切换和显存拷贝。

同时要设置热门适配器常驻、冷门适配器缓存与淘汰策略，并监控首 Token 延迟、吞吐、显存占用和各租户公平性。按 LoRA 分组能提高算子效率，但也可能增加排队时间，所以需要根据流量分布在“混批”和“同适配器聚合”之间权衡。

### 解析

Punica 是一种相关实现思路，但不应把具体框架当成唯一答案。面试重点是共享基座、适配器管理、LoRA 感知调度、融合算子，以及吞吐和尾延迟之间的取舍。

## 4. 后训练和LoRA怎么讲

#模型训练 #LoRA #模型优化

### 知识点
- 分类：模型训练、LoRA、模型优化
- 后训练：包括监督微调、偏好优化和强化学习等，用于改善模型行为
- LoRA原理：在部分权重旁加低秩矩阵，只训练少量参数
- 秩越大表达能力更强，但显存、训练成本和过拟合风险上升

### 答案

后训练是预训练之后，为了让模型更好地遵循指令、适配领域或符合人类偏好而进行的一系列训练，常见方法包括监督微调、偏好优化以及基于强化学习的对齐。LoRA 则是一种参数高效微调方法：冻结大部分基座参数，在部分线性层旁加入可训练的低秩增量矩阵。

它的优点是训练参数少、显存占用低、适配器容易切换；局限是能力上限受基座影响，目标模块、秩和数据质量仍需调优。秩增大可能提高表达能力，但也会增加参数量和过拟合风险，并不是越大越好。

### 解析

这道题要先区分“后训练”这个阶段与“LoRA”这种实现方式：LoRA 可以用于监督微调等后训练过程，但二者不是同一层级的概念。回答还应覆盖原理、优势和边界。

## 5. 如何评估LoRA是否真的提升Agent任务成功率？

#模型评估 #模型训练

### 知识点
- 分类：模型评估、模型训练
- 使用固定回归任务集和真实工具沙盒
- 统计成功率、调用成本和越权率
- 只看问答ROUGE没有意义

### 答案

我会先固定一套覆盖真实业务分布和高风险边界的 Agent 回归集，在同一个基座、Prompt、工具版本和推理参数下，对 LoRA 前后做对照。评测放在工具沙盒里，重点看端到端任务成功率、工具选择准确率、参数正确率、无效调用次数、越权率、成本和延迟。

离线通过后再做小流量 A/B 测试，并按任务类型和难度分桶，确认提升不是来自某一小类样本，也没有牺牲通用能力或安全性。ROUGE 只能衡量表面文本重合，不能证明 Agent 真的完成了任务。

### 解析

核心考点是控制变量、端到端执行评测和多维度回归。指标至少要覆盖任务成功、工具调用、越权行为、成本和延迟，并防止训练集与评测集重复导致虚假提升。

## 6. 微调后模型更会答，但更爱乱调用工具怎么排查？

#模型评估 #模型优化

### 知识点
- 分类：模型评估、模型优化
- 对比微调前后的工具选择分布
- 拆开评估回答质量和调用准确率
- 必要时降低工具轨迹样本权重

### 答案

我会先把“回答更好”和“工具乱调”拆成两个指标，对比微调前后的工具触发率、工具选择、参数正确率和无工具任务上的误调用率。然后回看训练数据，检查是否工具轨迹占比过高、负样本不足、把“调用工具”错误地当成成功模式，或者工具描述和 Prompt 在训练前后不一致。

修复时可以补充“不该调用工具”的负样本和澄清样本，重新平衡轨迹数据，必要时调整工具调用损失或决策阈值。执行侧仍要保留参数校验、权限控制和审批，不能把安全完全交给微调模型。

### 解析

考点是分层定位：数据分布、训练目标、工具 Schema、推理策略和执行防护都可能导致误调用。只降低工具样本权重可能损伤正常调用能力，因此应先用错误切片定位原因。

## 7. 线上发现某个LoRA造成安全退化怎么止损？

#模型部署 #系统运维

### 知识点
- 分类：模型部署、系统运维
- 模型网关按版本快速摘流
- 相关会话切回稳定适配器
- 问题样本进入安全回归集后再重新训练

### 答案

我会先在模型网关按 LoRA 版本停止新流量，切回已经验证的稳定适配器；对仍在进行的会话，根据状态决定继续使用旧版本还是安全终止，避免一次会话中静默切换导致行为不一致。与此同时冻结问题版本和相关日志，确认受影响的任务、用户和时间范围。

之后回放问题样本，判断退化来自训练数据、合并方式还是部署错配。修复后把样本加入安全回归集，经过离线评测、红队测试和灰度发布再恢复流量。

### 解析

回答应遵循止损、保留证据、评估影响、定位根因、修复验证的顺序。对于已经产生的数据泄露或危险动作，还要进入正式安全事件响应流程，不能只做模型回滚。

## 8. Agent轨迹数据如何清洗成微调样本？

#数据处理 #模型训练

### 知识点
- 分类：数据处理、模型训练
- 保留用户目标、关键观察、正确动作
- 删除错误工具调用和泄漏内容
- 每条样本标注任务类型和数据来源

### 答案

我会先按任务完成结果和人工规则筛选轨迹，再把用户目标、必要观察、决策、工具调用和最终结果还原成统一 Schema。无关日志、重复步骤、敏感信息和不可复现内容要清理；工具参数需按最新 Schema 校验，成功轨迹也要检查是否存在“碰巧成功”的错误步骤。

错误轨迹不一定全部删除，其中一部分可以整理成拒绝样本、偏好对或错误纠正样本，但不能当作正向示范。每条数据还要记录来源、授权、工具版本、任务类型和质量评分，并做好训练集、验证集按用户或任务去重，防止数据泄漏。

### 解析

轨迹数据清洗的关键是正确归因、Schema 一致、隐私与授权、去重和防止评测泄漏。失败轨迹不能直接作为正向示范，但经过正确标注后可以转化为纠错或偏好数据。

## 9. DPO和PPO的区别是什么

#强化学习 #模型训练 #偏好优化

### 知识点
- 分类：强化学习、模型训练、偏好优化
- PPO：强化学习思路，需要训练模型和策略更新，训练更复杂
- DPO：直接利用偏好数据优化模型，让偏好样本得分更高，实现更简单稳定
- 面试建议：DPO更适合很多轻量对齐场景

### 答案

PPO 在大模型对齐中通常属于在线强化学习方案：模型生成样本，根据奖励模型或可验证奖励得到反馈，再通过裁剪后的策略更新优化，同时用约束控制策略不要偏离参考模型。它能直接优化奖励，但需要 rollout、奖励计算和更多训练组件，成本和稳定性要求更高。

DPO 使用“偏好回答优于拒绝回答”的离线偏好对，直接优化策略相对参考模型的偏好概率，不需要单独训练在线策略循环，工程上更简单稳定。不过它依赖偏好数据质量，也不代表在所有任务上都优于 PPO。选择取决于是否有可靠奖励、在线采样能力和训练预算。

### 解析

回答应从数据来源、训练流程、是否在线采样、工程复杂度和适用条件比较，而不是简单得出“DPO 更好”。严格来说，DPO 是偏好优化方法，并不执行 PPO 那样的在线强化学习循环。

## 10. LoRA 微调时，如何监控过拟合并防止模型通用能力退化？

#大模型微调

### 知识点
- 分类：大模型微调
- 独立评估数据集
- 固定Steps验证Loss
- 任务跑分监测
- Early Stopping触发
- Checkpoint回滚

### 答案

我会准备三类相互独立的数据：训练集、同分布验证集，以及覆盖基座通用能力和安全能力的保留集。训练中定期观察训练损失与验证损失的差距，同时评估目标任务、通用任务和安全指标；仅看 Validation Loss 不够，因为它可能下降，但通用能力已经退化。

如果验证指标连续恶化，就触发 Early Stopping，并从最佳 Checkpoint 而不是最后一个 Checkpoint 恢复。除此之外还可以降低学习率或 LoRA 秩、减少训练轮数、改善数据多样性，并在发布前与原基座做完整回归。

### 解析

面试重点是同时监控目标能力和基座保留能力，用独立数据、趋势判断、最佳 Checkpoint 和回归测试控制退化。只观察训练损失或同分布验证损失无法证明通用能力没有下降。

## 11. LoRA训练数据里混入了用户隐私已经发布到线上怎么办？

#数据安全 #模型运维

### 知识点
- 分类：数据安全、模型运维
- 先下线适配器并冻结下载和缓存
- 定位数据来源重新清洗后训练新版本
- 旧版本按合规流程删除并保留不含明文的审计记录

### 答案

这要按隐私安全事件处理。第一步立即停止问题 LoRA 的新流量和分发，限制相关制品、缓存和日志的访问，同时保留必要证据；第二步确认隐私数据类型、来源、影响版本、暴露范围以及模型是否能够复现这些信息，并启动合规通报流程。

修复上优先从未受污染的基座或 Checkpoint 使用清洗后的数据重新训练，不能只假设删掉训练文件就解决了。旧适配器及其副本按数据保留政策安全删除，必要时轮换已经泄露的密钥或凭证。最后补充数据准入、脱敏、血缘和隐私评测，防止再次发生。

### 解析

关键是区分删除源数据与消除模型记忆；模型遗忘难以可靠证明时，从干净版本重训通常更稳妥。回答还应包括影响评估、合规通知、制品追踪和凭证处置。
