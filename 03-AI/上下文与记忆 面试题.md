## 1. 不同任务类型的压缩策略应该统一吗

#AI工程 #任务分类

### 知识点
- 分类：AI工程、任务分类
- 不应该统一
- 代码调试需保留完整错误和代码
- 对话任务可激进压缩
- 任务分类器路由

### 答案

不应该统一。我会先按任务对信息完整性的敏感程度做分类：代码调试要保留错误堆栈、相关代码和运行环境；事务型 Agent 要保留目标、参数、执行状态和审批结果；普通闲聊则可以更积极地摘要。

工程上可以由任务分类器选择压缩策略，但还要结合当前 Token 预算、任务阶段和风险等级动态调整。高风险或不可逆操作宁可多保留上下文，也不能为了节省 Token 丢掉关键约束。

### 解析

考点是候选人能否理解“重要信息”取决于任务，而不是套用统一窗口。完整回答应同时覆盖任务类型、风险等级、动态预算以及压缩后的验证机制。

## 2. 多轮对话里怎么判断哪些轮次可以压缩

#AI工程 #对话系统

### 知识点
- 分类：AI工程、对话系统
- 根据引用频率打分
- 从未被引用的轮次风险低
- 被多次引用的要完整保留
- 实时追踪引用关系

### 答案

我不会只按时间或引用次数判断，而会给每轮内容做重要性标记。用户目标、明确约束、已经确认的事实、尚未完成的任务、工具执行结果和纠错信息应该优先保留；寒暄、重复确认以及已经闭环的中间过程可以摘要或删除。

引用关系可以作为辅助信号，但“过去没被引用”不代表以后不重要。更稳妥的做法是把关键状态结构化保存，再对自然语言历史做压缩，并用规则检查摘要是否覆盖关键实体和未完成事项。

### 解析

引用频率只能作为辅助信号，因为未来依赖无法仅从历史引用推断。面试官更关注能否区分目标、约束、事实、决策和开放任务；结构化状态与对话摘要分离是更可靠的工程方案。

## 3. 工具调用历史怎么压缩

#AI工程 #工具调用

### 知识点
- 分类：AI工程、工具调用
- 已完成且结论已使用的工具调用可摘要
- 正在进行或结论存疑的不能压缩
- 只保留有用字段

### 答案

工具历史要按“可审计状态”压缩。对已完成且结果已经消费的调用，可以保留工具名、关键参数、状态、结果摘要、时间和调用 ID，原始大结果放到外部存储并保存引用；正在执行、失败待重试、结果存疑或涉及不可逆操作的调用，则要保留完整上下文。

压缩时不能丢掉幂等键、错误码、权限与审批结果，否则后续可能重复执行或错误恢复。也就是说，可以精简大字段，但执行语义和追踪信息必须保留。

### 解析

考点是工具调用历史不仅服务于模型理解，还承担恢复、幂等和审计职责。答案需要区分原始载荷与执行元数据，避免把“删掉没用字段”说成无条件操作。

## 4. 滑动窗口压缩和摘要压缩分别适合什么场景

#AI工程 #对话系统

### 知识点
- 分类：AI工程、对话系统
- 滑动窗口适用于短期对话
- 摘要压缩适用于长任务
- 混合方案更实用

### 答案

滑动窗口实现简单、延迟低，适合短对话或主要依赖最近几轮的场景，但它可能直接丢掉早期约束。摘要压缩更适合长对话和长任务，可以保留早期结论，不过会引入摘要错误和信息损失。

线上通常采用混合方案：最近几轮保留原文，较早内容做摘要，目标、约束、用户偏好和任务状态单独结构化保存。这样既控制 Token，又不会把关键状态完全交给摘要模型。

### 解析

回答应比较实现成本、信息损失和适用场景，并指出混合方案仍需要结构化状态兜底。不能默认“历史细节不重要”，因为早期约束可能在任务后段才生效。

## 5. 流式生成场景下，上下文怎么动态压缩

#AI工程 #流式处理

### 知识点
- 分类：AI工程、流式处理
- 固定Token数触发压缩
- 后台异步执行不阻塞
- 新Token先用旧上下文
- 无缝切换

### 答案

上下文压缩通常应发生在轮次之间或 Agent 的步骤边界，而不是在一次自回归生成过程中直接替换上下文。因为当前生成已经依赖既有的 KV Cache，中途换上下文往往需要停止并重新发起推理，不能假设可以无缝切换。

工程上我会在 Token 达到预警阈值前异步生成下一轮要用的摘要，同时把目标、约束和工具状态单独保存。当前输出继续使用原上下文；等本轮结束后，对摘要做完整性校验，再把它用于下一轮。如果必须中断重启，要显式处理重复输出和状态一致性。

### 解析

核心考点是区分面向用户的流式输出与模型内部自回归状态。异步压缩可以提前做，但新上下文通常从下一次模型调用开始生效，不能假设当前生成可以无缝替换上下文。

## 6. 上下文太多怎么处理？

#大模型应用 #上下文管理

### 知识点
- 分类：大模型应用、上下文管理
- 摘要
- 检索
- 分层记忆
- 窗口截断
- Token成本监控

### 答案

我会先把上下文分成四类：当前目标和硬约束、任务状态、可检索的历史资料，以及普通对话。前两类结构化保留；历史资料放到外部存储，需要时检索回来；普通对话采用近期窗口加远期摘要。实在超预算时再按重要性截断，而不是直接从最早内容开始删。

上线后要同时监控 Token 成本、延迟、任务成功率和关键约束丢失率。上下文越长不一定越好，相关性低的内容还可能干扰模型判断。

### 解析

这道题考察分层管理思路。较好的回答会区分结构化状态、短期上下文、长期记忆和外部检索，并说明如何用质量指标验证压缩是否安全。

## 7. 上下文压缩的核心目标是什么

#AI工程 #系统优化

### 知识点
- 分类：AI工程、系统优化
- Token预算约束
- 保留关键信息
- 每个Token都要有用
- 避免稀释注意力权重

### 答案

核心目标是在给定 Token、延迟和成本预算下，最大限度保留完成当前任务所需的信息。压缩不是单纯追求更短，而是减少重复和低相关内容，同时保住目标、约束、事实依据、任务状态和可追溯性。

好的压缩还要让结果可验证、可更新，避免摘要错误不断累积。最终应以任务成功率和关键信息保留率衡量，而不是只看节省了多少 Token。

### 解析

答案应把效率目标和质量目标放在一起。过多无关上下文可能造成“长上下文中间信息遗失”等问题，但不宜简单表述为固定的“注意力权重被稀释”。

## 8. 什么信息适合写入长期记忆？

#AI/机器学习 #数据存储

### 知识点
- 分类：AI/机器学习、数据存储
- 适合写入用户稳定偏好、长期身份信息、常用约束和确认过的事实
- 不适合写入临时情绪、一次性任务、低置信度猜测
- 写入前需要有来源、时间、置信度和可删除入口

### 答案

长期记忆适合保存用户明确同意记录、跨会话仍有价值且相对稳定的信息，例如常用语言、长期偏好和反复确认的工作习惯。临时情绪、一次性任务、模型推测以及敏感信息，不应默认写入。

每条记忆最好带来源、时间、适用范围、置信度和有效期，并允许用户查看、更正和删除。涉及个人信息时还要遵循最小化原则和权限隔离，不能因为“以后可能有用”就长期保存。

### 解析

考点除了记什么，还包括谁授权、保存多久、如何纠错和删除。将“长期身份信息”笼统写入可能带来隐私风险，应强调用户知情和数据最小化。

## 9. 压缩策略上线后怎么评估它真的没有影响效果

#AI工程 #效果评估

### 知识点
- 分类：AI工程、效果评估
- 对比任务完成率
- 对比用户满意度
- 关注长任务逐步效果
- AB测试验证

### 答案

我会先做离线回放，用同一批长对话比较压缩前后的任务成功率、答案一致性、关键约束保留率和 Token 节省比例；再做小流量 A/B 测试，观察用户满意度、追问率、转人工率、任务耗时和成本。

评测要按对话长度、任务类型和风险等级分桶，因为压缩问题通常在多轮后才暴露。上线还要设置质量护栏和回滚条件，不能只看到成本下降就认为策略有效。

### 解析

完整评估要同时衡量质量、效率和风险，常用指标包括任务成功率、转人工率、关键约束保留率、延迟和 Token 成本，并通过离线回放、小流量实验和线上监控逐步验证。

## 10. 压缩后怎么验证关键信息没有丢失

#AI工程 #测试验证

### 知识点
- 分类：AI工程、测试验证
- 关键实体列表覆盖率检查
- 验证地点、时间、约束等
- 自动化校验更可靠

### 答案

我会先从原上下文提取一份必须保留的结构化清单，包括目标、人物、时间、地点、否定条件、数值、已确认决策和未完成事项。压缩后对这份清单做覆盖和一致性检查，再用代表性任务回放，确认模型仍能做出相同的关键决策。

自动校验适合大规模回归，但不能只做字符串匹配，因为摘要可能换一种说法，也可能保留实体却改变关系。高风险场景还需要规则校验或人工抽检。

### 解析

考点是验证“事实及其关系”是否保留，而不只是实体有没有出现。自动化与人工抽检各有作用，不应绝对地说自动化一定比人工可靠。

## 11. 摘要压缩最容易丢什么信息

#AI工程 #数据处理

### 知识点
- 分类：AI工程、数据处理
- 约束条件容易丢失
- 用户隐性偏好丢失
- 否定词丢失
- 关键实体需单独保留

### 答案

摘要最容易丢掉低频但关键的信息，例如否定条件、例外情况、精确数值、时间顺序、信息来源，以及尚未完成的事项。比如用户说“不要推荐 X”，摘要如果只保留“讨论了 X”，语义就完全反了。

所以我会把目标、约束、实体关系和任务状态单独结构化保存，摘要只负责压缩叙述性内容；压缩后再做一致性检查，避免模型自己决定哪些细节可以丢。

### 解析

高质量回答要特别指出否定、数字、时间顺序和来源容易发生语义翻转。解决方案不是无限加长摘要，而是将关键状态从自然语言摘要中分离出来。
