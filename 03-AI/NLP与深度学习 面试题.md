## 1. 导购 Agent 需要理解哪些用户信息？

#NLP #推荐系统

### 知识点
- 目标、预算、用途、偏好、禁忌和时效
- 明确信息与模型推断分离
- 动态更新需求快照

### 答案

我会把需求拆成购买目标、预算、使用场景、硬约束、偏好和时间要求。用户明确说出的条件作为高置信事实，模型推断只作为候选信号，涉及健康、身份等敏感属性不能擅自扩展。

多轮交流中持续更新结构化需求快照，推荐理由要能对应具体需求；信息不足时先追问最影响筛选结果的条件。

### 解析

考点是需求结构化和置信度管理，而不是简单提取关键词。

## 2. 端侧模型如何量化，同时尽量保留核心能力？

#模型量化 #端侧AI

### 知识点
- PTQ、QAT 与混合精度
- 校准数据和敏感层分析
- 真实设备端到端评测

### 答案

我会先建立未量化基线，再用代表真实分布的校准集做 INT8 或 INT4 的训练后量化；损失明显时采用量化感知训练或混合精度，让输出层、归一化层或经实验确认的敏感模块保留更高精度。

最终在目标设备上评估准确率、格式遵循、安全边界、首响、内存、功耗和温升。量化是否可接受取决于端到端任务，而不是只看权重误差。

### 解析

不存在保证“完全不影响”的量化，正确做法是测量退化并选择质量与资源的工作点。

## 3. 多轮对话变长后，为什么早期信息可能被忽略？

#长上下文 #Attention

### 知识点
- Attention 本身没有固定时间衰减
- 位置偏置、训练分布和 Lost in the Middle
- 相关性噪声和上下文预算

### 答案

自注意力并没有“越早权重必然越低”的固定机制，但长上下文中候选信息更多，模型受位置编码、训练分布和相关性噪声影响，可能出现 Lost in the Middle：开头或中间的关键条件没有被稳定利用。

工程上把目标、约束和任务状态结构化保存，较早对话摘要化，需要时再检索，并用长对话回归测试关键条件保留率。

### 解析

“Token 多所以注意力被平均稀释”只是直觉，不能当作严格数学解释。应区分模型机制与经验现象。

## 4. 多轮语音对话的上下文怎么管理？

#语音交互 #上下文工程

### 知识点
- 近期原文、远期摘要和结构化状态
- ASR 版本与纠错记录
- 动态预算而非固定轮数

### 答案

我会分三层：最近的关键轮次保留原文，较早内容做可追溯摘要，目的地、约束、工具状态等放入结构化状态。保留几轮不是固定三到五轮，而由 Token 预算和任务依赖决定。

语音场景还要保存 ASR 最终版本和用户纠错，不能让已被纠正的中间转写继续影响任务。压缩后通过关键实体和未完成事项检查完整性。

### 解析

重点是把业务状态从自然语言历史中分离，而不是机械截断旧对话。

## 5. 多模态 Agent 处理图文内容的流程是什么？

#多模态 #计算机视觉 #NLP

### 知识点
- 预处理与版面、OCR、视觉对象提取
- 跨模态对齐和证据绑定
- 融合、推理与风险控制

### 答案

先做文件与图像预处理，再分别提取 OCR 文字、版面结构、视觉对象和图像描述，每项结果保留图片 ID、区域和置信度。随后围绕当前问题做跨模态检索与对齐，把文字和视觉证据绑定到统一任务状态。

推理结果必须能回到原图区域或文本片段；证据冲突时保留分歧，高风险动作要求确认。不是把所有模态简单拼成一段文本。

### 解析

完整流程的核心是感知、对齐、融合、证据和决策。不同视觉编码器只是感知层的实现选择，不能替代跨模态证据管理。

## 6. 多模态内容怎么切片？

#多模态RAG #数据处理

### 知识点
- 按文档结构、镜头和时间边界切分
- 保留模态、来源、页码、时间码和关系
- 父子块与相邻上下文

### 答案

文档按标题、段落、表格和图片区域切，视频按镜头、字幕和语音停顿切，音频按说话人和语义段切。每个 Chunk 保留模态类型、来源、页码或时间码，并保存图、文、表之间的关系。

召回可使用较小块提高命中率，生成时回到父级或相邻片段补完整语境。Chunk 大小通过证据召回和答案评测调整。

### 解析

多模态切片的难点是语义边界与跨模态关联，而不是字符长度。

## 7. 会后自动生成待办，怎么避免责任人识别错误？

#信息抽取 #会议助手

### 知识点
- 说话人、语义、称呼和组织关系
- 负责人、动作、截止时间和证据
- 低置信度确认

### 答案

我会抽取“谁、做什么、何时完成”，结合说话人分离、明确指派语句、称呼和组织目录生成候选。每条待办保留对应时间段和原话，避免只给结论。

负责人不明确或只是建议时标记为待确认，不自动派发；正式发送前由主持人或责任人确认，高风险任务还要确认截止时间和权限。

### 解析

责任人识别不仅是 NER，还涉及指代消解、对话行为识别和证据确认。

## 8. 面试官问“准确率提升 20%”，应该怎么证明？

#模型评估 #实验设计

### 知识点
- 明确绝对提升还是相对提升
- 固定基线、数据、指标和置信区间
- 消融实验与数据泄漏检查

### 答案

先明确是从 60% 到 80%的 20 个百分点，还是相对提升 20%。然后固定模型外的 Prompt、工具、解码参数和测试集，在独立且无泄漏的数据上重复评测，并报告样本量、置信区间和分场景结果。

通过消融实验比较基座、训练数据和 LoRA 版本，证明提升来源，同时检查是否牺牲安全、延迟或其他任务能力。

### 解析

只报一个平均数不能证明真实提升，口径、统计不确定性和归因同样重要。

## 9. 评估数据集规模怎么设计？Bad Case 怎么分析？

#模型评估 #数据工程

### 知识点
- 按目标精度和置信区间估算样本
- 核心、长尾、高风险和对抗场景分层
- 按链路阶段和根因归类

### 答案

规模应根据指标波动、期望误差和场景覆盖决定，而不是越大越好。先建立高质量核心集，再按意图、难度、长尾、高风险和线上流量分层扩充，保证每个关键切片有足够样本。

Bad Case 按输入理解、检索、工具选择、参数、生成、安全和系统故障归类，再找第一个出错环节并跟踪修复后的回归结果。

### 解析

高质量基准集用于稳定回归，滚动样本用于覆盖线上变化。Bad Case 分析必须形成可行动的根因分类。

## 10. 图片和文字互相矛盾时，Agent 怎么判断？

#多模态 #证据融合

### 知识点
- 分开保存来源和置信度
- 根据任务选择权威证据
- 高风险冲突请求确认

### 答案

我不会直接选择模型更自信的一边，而是分别保存文字和图片证据，检查来源、清晰度、时间、区域和识别质量，再根据业务规则确定哪个来源更权威。

无法消除冲突时明确展示分歧和证据；涉及金额、身份或执行动作时暂停并让用户确认，不能擅自融合成一个事实。

### 解析

模型置信度可能未校准，证据来源和业务权威性通常比单个概率更重要。

## 11. 语音 Agent 如何读准金额、日期和专有名词？

#TTS #ASR #文本规范化

### 知识点
- TTS 前文本规范化和实体标注
- 发音词典、音素和上下文读法
- ASR 热词与关键字段确认

### 答案

TTS 前先做文本规范化，把金额、日期、时间、电话号码、缩写和单位转换成适合口播的形式；专有名词维护带上下文的发音词典，必要时使用音素或拼音覆盖。

ASR 侧使用业务热词和候选纠错。金额、地址等关键字段在执行前复述确认，并用规则测试不同币种、小数和多音字。

### 解析

准确口播不是单靠 TTS 模型，文本规范化、词典和业务确认同样关键。

## 12. 如何减少生成内容的重复和模板化表达？

#文本生成 #内容质量

### 知识点
- 区分语义重复和合理风格一致
- 检索近期内容、规划不同信息角度
- 用评测控制事实与多样性

### 答案

先判断问题来自训练数据、Prompt 模板还是解码策略。生成前检索近期内容，提取已经使用的结构和论点，要求新内容补充不同信息，而不是只替换同义词。

可以用语义相似度和重复片段指标做门槛，但不能为了多样而牺牲事实和品牌一致性。高频空话通过编辑规范和评测集治理。

### 解析

禁用表达库只能处理表面重复，真正的多样性来自信息规划、数据和任务目标。

## 13. 如何区分会议讨论和最终决议？

#对话理解 #信息抽取

### 知识点
- 承诺、确认和总结等对话行为
- 负责人、动作、截止时间和证据
- 状态机与人工确认

### 答案

先识别“决定、同意、由谁负责、何时完成”等承诺和确认信号，并结合主持人总结、后续反对或修改判断状态。每条决议记录负责人、动作、截止时间和证据时间段。

没有明确确认的只作为讨论或候选事项，不自动升级为决议；会议结束前可生成清单让主持人确认。

### 解析

关键词只能提供候选，决议识别本质上是对话行为、指代和状态演化问题。

## 14. 什么时候用 LoRA，而不是只改 Prompt 或使用 RAG？

#LoRA #模型选型

### 知识点
- 稳定行为、风格、格式和领域表达
- Prompt 已达到边界且有高质量数据
- 更新事实优先 RAG，硬规则放代码

### 答案

当目标是稳定改变模型行为、表达风格、输出模式或领域语言，并且 Prompt 已难以稳定约束、又有足够高质量样本时，我会考虑 LoRA。

频繁变化的知识更适合 RAG，权限和业务硬规则应由代码执行。LoRA 不能弥补基座缺失的核心能力，也不适合充当实时数据库。

### 解析

选型要区分行为、知识和规则三类问题，不能把所有效果问题都交给微调。

## 15. 实体识别一般怎么做？

#NER #NLP

### 知识点
- 规则、词典、序列标注和大模型结构化抽取
- 实体边界、类型和标准化
- 置信度、评测与人工闭环

### 答案

规则稳定、实体集合小的场景可用正则和词典；开放领域可以用序列标注模型、编码器模型或大模型结构化抽取。输出不仅包含实体类型，还要有文本位置、标准化 ID 和置信度。

评测看实体级 Precision、Recall、F1 和边界错误，并按实体类型切片。低置信度或高风险字段进入确认，线上错误回流标注。

### 解析

实体识别不是普通分类，实体边界、嵌套实体和链接到标准实体同样重要。

## 16. 图片信息要不要全部转成文本？

#多模态 #OCR

### 知识点
- OCR 与 Caption 会丢失视觉细节
- 保留原图、区域和向量引用
- 文本召回与视觉复核结合

### 答案

不应该全部转成文本。OCR 适合文字，Image Caption 适合粗粒度语义，但版面、颜色、空间关系和细粒度视觉特征可能丢失。

可以用文本提高检索效率，同时保留原图、区域框、图像向量和来源引用，需要时让多模态模型回到原始区域复核。

### 解析

CAPTCHA 是验证码，不是图像描述技术；这里正确概念是 Caption。

## 17. 模型生成的工具参数经常不符合 JSON Schema，怎么优化？

#结构化输出 #工具调用

### 知识点
- 清晰 Schema、描述和高质量训练样本
- 约束解码或原生结构化输出
- 服务端验证与有限纠错

### 答案

先检查 Schema 是否过于复杂、字段含义是否清楚，并提供覆盖可选字段和边界情况的正确训练样本。推理时优先使用模型或框架支持的 JSON Schema 约束解码，从语法层阻止非法结构。

服务端仍要用独立校验器检查业务语义；失败时把具体错误反馈给模型有限重试，持续失败则终止。负样本可以用于偏好训练，但不能替代正确示范。

### 解析

约束解码保证结构合法，不保证账号、金额和权限等业务参数正确。

## 18. 微调后的模型怎么上线？

#模型部署 #MLOps

### 知识点
- 离线质量、安全和性能回归
- 制品版本、灰度和对照实验
- 监控、护栏和快速回滚

### 答案

先固定模型、数据、代码和配置版本，完成目标任务、通用能力、安全、延迟与成本回归。通过后小流量灰度，与旧版本按任务切片对照，设置成功率、越权率和资源指标护栏。

模型网关支持快速摘流和回滚，问题样本进入回归集。不能只看平均分，也要观察长尾和高风险场景。

### 解析

上线是持续验证过程，不是离线指标通过后直接替换生产模型。

## 19. 微调时 Learning Rate Scheduler 怎么设计？

#模型训练 #超参数

### 知识点
- Warmup 与线性或余弦衰减
- 与有效 Batch、优化器和训练步数联调
- 依据验证指标和稳定性调整

### 答案

常见起点是短 Warmup 加线性或余弦衰减：前期逐步升高学习率避免大梯度破坏已有能力，中后期下降帮助收敛。但 Warmup 比例和曲线没有固定最优值。

我会结合有效 Batch Size、数据量、LoRA 配置、优化器和总步数做小规模实验，监控训练与验证损失、梯度范数和任务指标，用最佳检查点与 Early Stopping 控制训练。

### 解析

Scheduler 不能脱离峰值学习率和训练预算单独讨论，验证集表现才是最终依据。

## 20. 微调训练数据怎么构建并保证多样性？

#SFT #数据工程

### 知识点
- 先定义能力边界和样本 Schema
- 真实、人工和合成数据结合
- 分场景、难度和失败模式覆盖

### 答案

先明确要改变的能力和不应改变的能力，再定义输入、输出、工具轨迹和元数据 Schema。数据可以来自经授权的真实日志、人工编写和合成样本，但都要经过统一质检。

按意图、领域、难度、语言、边界条件和失败模式分桶，观察分布并补低覆盖区域；训练、验证和测试按用户或任务去重，防止泄漏。

### 解析

多样性不是随机堆问法，而是覆盖真实决策边界和长尾失败模式。

## 21. 训练数据质量怎么评估和提升？

#数据质量 #模型训练

### 知识点
- 正确性、一致性、覆盖、重复、隐私和授权
- 自动规则、模型辅助和人工抽检
- 数据批次消融与血缘

### 答案

我会从正确性、指令与答案一致性、覆盖度、多样性、重复率、噪声、隐私和授权评估。自动规则处理格式和重复，模型辅助发现异常，关键样本由人工按统一规范复核并测标注一致性。

每个数据批次保留来源和处理血缘，通过抽样报告和消融实验判断它对目标能力与通用能力的影响。

### 解析

数据量与质量不是简单二选一，关键是可度量、可追溯，并知道哪批数据改变了什么能力。

## 22. 遇到低质量 SFT 数据怎么处理？

#SFT #数据清洗

### 知识点
- 明显错误删除，可确定格式问题修复
- 模糊样本隔离、降权或重标
- 保留原因和版本

### 答案

乱码、泄密、无授权和事实明显错误的样本直接隔离或删除；可以确定语义未变的格式问题才自动修复；答案含糊、跑题或标注冲突的样本进入重标、降权或人工审核。

所有动作记录规则、原因和版本，并按任务分层抽检。不能让模型静默“修好”后直接训练，否则可能把错误语义包装得更流畅。

### 解析

低质量数据要按错误类型处理。可追溯性决定后续退化能否定位和回滚。

## 23. 训练 LoRA 时应该作用在哪些层？

#LoRA #模型训练

### 知识点
- Attention 投影与 MLP 都是候选
- 任务、参数预算和部署能力共同决定
- 通过消融实验选择

### 答案

我会从较小目标模块集合做基线，再比较参数量、训练稳定性、目标指标、通用能力退化和推理开销，选择收益最好的配置。

### 解析

目标层、秩和缩放系数需要联合实验，不能用“知识任务选某层”这类未经验证的规则代替评测。

## 31. Attention 的本质是什么？如何从向量空间解释？

#Attention #Transformer

### 知识点
- Q 与 K 的缩放点积
- Softmax 权重和 V 的加权和
- 多头投影与掩码

### 答案

输入隐藏状态经过线性变换得到 Q、K、V。每个 Query 与 Key 做缩放点积，经过掩码和 Softmax 得到权重，再对 Value 加权求和，从而为当前位置聚合相关信息。

多头注意力在不同子空间学习不同关系。权重表示当前计算中的信息路由，不应直接等同于人类可解释的重要性或因果关系。

### 解析

完整表达式是 `softmax(QKᵀ/√dₖ)V`，缩放用于控制点积随维度增大造成的数值问题。

## 32. DPO 训练出现梯度爆炸或损失异常，怎么排查？

#DPO #训练稳定性

### 知识点
- 偏好对、模板、长度和数据异常
- 学习率、Beta、梯度范数和数值精度
- 参考模型与实现一致性

### 答案

先定位异常批次，检查 chosen/rejected 是否颠倒、差异过弱或极端、模板与 Tokenization 是否一致，以及超长样本和重复数据。再核对参考模型、Log Probability、Mask 和混合精度实现。

超参数上降低学习率，调整 Beta、Warmup 和有效 Batch，使用梯度裁剪，并监控梯度范数、偏好 Margin、KL 和验证集。单纯减小 Batch 不一定更稳定。

### 解析

“DPO 爆炸”不是单一故障名，必须先区分数据、实现、数值和超参数问题。

## 33. LoRA 和 QLoRA 怎么取舍？

#LoRA #QLoRA

### 知识点
- QLoRA 以量化基座降低训练显存
- LoRA 训练链路更直接
- 质量、显存、吞吐和部署兼容性评测

### 答案

LoRA 冻结常规精度基座并训练低秩适配器，显存足够时链路更直接。QLoRA 在训练中使用低比特量化基座，显著降低显存，让较大模型能在有限硬件上微调，但量化计算、内核和兼容性更复杂。

选择时比较目标质量、显存、训练吞吐和工具链支持。训练用了 QLoRA 不代表线上必须采用完全相同的量化部署方案，推理制品要单独评测。

### 解析

QLoRA 的核心是量化基座加 LoRA 训练，不应笼统说成“LoRA 权重量化”。

## 34. LoRA 的原理是什么？参数怎么选？

#LoRA #模型训练

### 知识点
- 冻结基座，学习低秩增量矩阵
- Rank、Alpha、Dropout 和目标模块
- 通过消融与验证集选择

### 答案

LoRA 冻结基座权重，把权重更新近似为两个低秩矩阵的乘积，只训练这部分增量。常调参数包括目标模块、Rank、Alpha、Dropout 和学习率。

我会从较小 Rank 和有限目标层开始，逐步比较任务指标、通用能力、参数量和过拟合。Rank 越大容量通常越强，但成本更高，也不保证效果单调提升。

### 解析

参数之间有耦合，不能脱离数据规模、任务和基座模型给出统一最优值。

## 35. LoRA 相比全量微调有什么优缺点？

#LoRA #模型训练

### 知识点
- 参数少、成本低、适配器易切换
- 能力上限受基座和目标模块影响
- 多适配器管理与推理开销

### 答案

LoRA 训练参数少、显存和存储成本低，同一基座可以切换多个适配器，适合快速领域或行为适配。相比全量微调，它通常更容易训练和回滚。

局限是能力上限受基座影响，目标模块选择不当会限制效果；多适配器还会增加版本、缓存和调度复杂度。频繁变化的事实应使用 RAG，而不是写进权重。

### 解析

选型应与全量微调、Prompt 和 RAG 比较具体目标，不能只按训练成本判断。

## 37. Transformer 的结构和工作流程是什么？Q、K、V 怎么计算？

#Transformer #Attention

### 知识点
- Embedding、位置信息、多头注意力、FFN、残差和归一化
- Q/K/V 线性投影与缩放点积注意力
- 编码器、解码器和 Decoder-only 结构差异

### 答案

输入先经过 Token Embedding 和位置信息，再依次通过多层多头注意力、前馈网络、残差连接和归一化，最后由输出层预测。现代大语言模型多为 Decoder-only，并使用因果 Mask 防止当前位置看到未来 Token。

在每个注意力层，隐藏状态分别乘可学习矩阵得到 Q、K、V；计算 `QKᵀ/√dₖ`，加 Mask 后做 Softmax，再对 V 加权。多头结果拼接投影，FFN 再对每个位置做非线性变换。

### 解析

回答要区分 Transformer 通用架构与具体模型变体。残差和归一化帮助深层训练稳定，但不能简单宣称绝对防止梯度消失或爆炸。
